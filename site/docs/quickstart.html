Início rápido

Peça ao seu agente de código para instalar o processo de revisão e rodar a revisão por você. Por baixo, o motor de segurança da camada III é só Go: sem LLM, sem chamada de rede, sem chave de API. Ele sai com código 1 quando algum achado é BLOCK. A linha de comando continua disponível para CI e uso direto.

Pelo seu agente

Funciona com Claude Code, Codex, Cursor, Kiro, GitHub Copilot e Gemini CLI. O agente roda o instalador e o motor por você; nada é escrito sem o seu sim.

1. Instale: cole uma frase no agente

Abra o agente no repositório que você quer revisar e diga:

Instala o AI Code Review neste repositório: clone https://github.com/tiagovilasboas/ai-code-review num diretório temporário, leia .agents/skills/ai-code-review-setup/SKILL.md e siga esse procedimento.

A skill ai-code-review-setup detecta o harness presente, roda o instalador com --dry-run, mostra o plano e pede um sim claro antes de escrever. Depois confere se o comando de revisão existe e se o motor roda (review --version). Se faltar Go, ela avisa e aponta para esta página; não instala nada sozinha.

2. Rode a revisão

  • Claude Code, Gemini CLI, GitHub Copilot (Chat no VS Code) e Kiro: /review-pr. Aceita base, profundidade e rodada, por exemplo /review-pr main deep (no Claude Code e no Gemini).
  • Codex: /prompts:review-pr, depois de copiar .codex/prompts/review-pr.md para ~/.codex/prompts/.
  • Cursor: diga “revisa meu PR” (ou “rode o processo de revisão nesta branch”). O Kiro também aceita a frase.

3. O que o agente devolve

  • A decisão primeiro, com o motivo, e uma contagem: N findings (I important, N nit, P pre-existing).
  • Cada achado com a evidência em path:line, a classe, o CWE e a ação.
  • Opcionalmente, uma triagem em contexto novo que só pode descartar ou rebaixar achados de falso positivo. Um BLOCK que sobra é final.
  • Ele para e deixa a decisão com uma pessoa: não edita arquivos, não faz merge e não publica.

Pela linha de comando (CI e uso direto)

Sem agente: o mesmo motor, direto no terminal ou no CI.

Rodar o motor de segurança

Precisa de Go 1.27 ou mais recente. Num checkout do repositório:

go run ./cmd/review security/examples/sample-pr.diff

Ou instale o binário e revise a sua própria branch:

go install github.com/tiagovilasboas/ai-code-review/cmd/review@latest

review security/examples/sample-pr.diff            # a diff file; exit 1 = BLOCK
review --git --from origin/main --to HEAD          # your branch, straight from git
review --git                                       # staged, unstaged and untracked changes
review --git --commit <sha> --format sarif --output review.sarif

Formatos: text (padrão), json (schemaVersion 1) e sarif (2.1.0, para o GitHub Code Scanning). O contrato completo está em docs/design/cli-contract.md.

Ler a saída

O relatório começa pela decisão e pelo motivo. Cada achado traz a classe, a evidência como path:line, o CWE, os identificadores oficiais do OWASP, a severidade e a ação. Esta é a saída exata para o diff de exemplo, em inglês, como a ferramenta imprime:

Instalar o processo de revisão

É o que a skill de instalação roda por você. O instalador copia os papéis de revisor, as regras que eles seguem e as skills (pr-review-process e ai-code-review-setup) para o seu repositório, para um harness ou para todos. Veja a prévia antes; ele nunca sobrescreve um arquivo, a menos que você passe --force.

scripts/install-review-process.sh --harness all --target ../your-repo --dry-run
scripts/install-review-process.sh --harness claude-code --target ../your-repo

--harness aceita claude-code, kiro, codex, cursor, copilot, gemini ou all. --with-security-kit também copia security/skills/ e a skill appsec-pr-review. No Windows, use scripts/install-review-process.ps1.

Classificar o nível de risco

A camada V ajusta a aprovação humana ao risco. Quem define o nível é a mudança, não o autor, e o classificador não precisa de modelo:

go run ./cmd/tier --from origin/main --to HEAD     # or: make tier

Níveis e caminhos: docs/review-tier.md.

Rodar os testes

O mesmo gate roda no local e no CI. Instale os git hooks uma vez por clone:

make hooks
make check

Rodar em todo pull request

A GitHub Action revisa o diff do pull request, escreve uma tabela de achados no resumo do job, envia o SARIF ao Code Scanning e falha o job em BLOCK. Fixe a versão num SHA de commit completo, como em qualquer action de terceiros:

permissions:
  contents: read
  security-events: write # SARIF upload

steps:
  - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
    with:
      fetch-depth: 0
  - uses: tiagovilasboas/ai-code-review@<full-commit-sha>

Entradas, saídas e permissões: docs/github-action.md. Em qualquer outro CI, rode review --git --from <base> --to HEAD e deixe o código de saída 1 falhar o job.
