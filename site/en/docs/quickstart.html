Quickstart

Ask your coding agent to install the review process and run the review for you. Underneath, the layer III security engine is Go only: no LLM, no network call, no API key. It exits with code 1 when any finding is BLOCK. The command line stays available for CI and direct use.

Through your agent

Works with Claude Code, Codex, Cursor, Kiro, GitHub Copilot and Gemini CLI. The agent runs the installer and the engine for you; nothing is written without your yes.

1. Install: paste one sentence to the agent

Open the agent in the repository you want to review and say:

Install AI Code Review in this repository: clone https://github.com/tiagovilasboas/ai-code-review into a temporary directory, read .agents/skills/ai-code-review-setup/SKILL.md and follow that procedure.

The ai-code-review-setup skill detects the harness present, runs the installer with --dry-run, shows the plan and asks for a clear yes before writing. Then it checks that the review command exists and that the engine runs (review --version). If Go is missing, it says so and points to this page; it never installs anything on its own.

2. Run the review

  • Claude Code, Gemini CLI, GitHub Copilot (Chat in VS Code) and Kiro: /review-pr. It takes a base, a depth and a round, for example /review-pr main deep (in Claude Code and Gemini).
  • Codex: /prompts:review-pr, after copying .codex/prompts/review-pr.md to ~/.codex/prompts/.
  • Cursor: say “review my PR” (or “run the review process on this branch”). Kiro also accepts the sentence.

3. What the agent returns

  • The decision first, with the reason, and a count: N findings (I important, N nit, P pre-existing).
  • Each finding with its evidence as path:line, class, CWE and action.
  • Optionally, a triage pass in fresh context that can only drop or downgrade false-positive findings. A BLOCK that survives is final.
  • It stops and leaves the decision to a person: it does not edit files, merge or publish.

From the command line (CI and direct use)

No agent needed: the same engine, straight from the terminal or CI.

Run the security engine

Requires Go 1.27 or later. From a checkout of the repository:

go run ./cmd/review security/examples/sample-pr.diff

Or install the binary and review your own branch:

go install github.com/tiagovilasboas/ai-code-review/cmd/review@latest

review security/examples/sample-pr.diff            # a diff file; exit 1 = BLOCK
review --git --from origin/main --to HEAD          # your branch, straight from git
review --git                                       # staged, unstaged and untracked changes
review --git --commit <sha> --format sarif --output review.sarif

Formats: text (default), json (schemaVersion 1) and sarif (2.1.0, for GitHub Code Scanning). The full contract is in docs/design/cli-contract.md.

Read the output

The report starts with the decision and the reason. Each finding lists its class, evidence as path:line, CWE, official OWASP identifiers, severity and action. This is the exact output for the sample diff:

Exit codes

CodeMeaning
0No BLOCK finding
1At least one BLOCK finding. Do not merge.
2Usage, read or git error

Install the review process

This is what the setup skill runs for you. The installer copies the reviewer roles, their guardrails and the skills (pr-review-process and ai-code-review-setup) into your repo for one harness or all of them. Preview first; it never overwrites a file unless you pass --force.

scripts/install-review-process.sh --harness all --target ../your-repo --dry-run
scripts/install-review-process.sh --harness claude-code --target ../your-repo

--harness takes claude-code, kiro, codex, cursor, copilot, gemini or all. --with-security-kit also copies security/skills/ and the appsec-pr-review skill. On Windows use scripts/install-review-process.ps1.

Classify the risk tier

Layer V scales human approval to risk. The change sets the tier, not the author, and the classifier needs no model:

go run ./cmd/tier --from origin/main --to HEAD     # or: make tier

Tiers and paths: docs/review-tier.en.md.

Run the tests

The same gate runs locally and in CI. Install the git hooks once per clone:

make hooks
make check

Run it on every pull request

The GitHub Action reviews the pull request diff, writes a findings table to the job summary, uploads SARIF to Code Scanning and fails the job on BLOCK. Pin it to a full commit SHA, like any third-party action:

permissions:
  contents: read
  security-events: write # SARIF upload

steps:
  - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
    with:
      fetch-depth: 0
  - uses: tiagovilasboas/ai-code-review@<full-commit-sha>

Inputs, outputs and permissions: docs/github-action.md. In any other CI, run review --git --from <base> --to HEAD and let exit code 1 fail the job.
